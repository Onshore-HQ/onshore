# Known limits

Onshore is in early access. This page says plainly what has and hasn't been tested, so you can decide what matters for you.

<Callout type="error">
**Don't load real customer data yet.** Onshore hasn't had an independent penetration test, and most testing has been on one machine against stand-ins for real vendors.
</Callout>

## Must close before real customer data

- **An independent penetration test.** Internal attack suites have run repeatedly; they don't replace an outside test.
- **Support tool adapters against live accounts.** All four are tested only against stand-ins.
- **Performance on real hardware.** Tokenize at 10 concurrent clients is close to, but above, its 30 ms target on a laptop.
- **Mobile SDKs on real devices.** Only an emulator and a simulator so far.
- **Your signed legal positions.** Record your scope definition and each connection's legal ground; Onshore assumes nothing.

## Tested, with limits

| Helm chart | Lint and schema validation | Installing on a cluster |

| Country packs | 31 checks through the API and the screens | Real-world ID samples from each country |
| French | Every console string | Native review; server text, emails and the PDF are still English |

## Detection

- A bare number after a word like `order`, `ref`, `ticket` or `invoice` isn't flagged, because those words usually mean a genuine order number. An explicit cue such as "NI number" wins. Add your own data type if you'd rather catch them.
- Names are found with dictionaries and context, not a trained language model.
- Accuracy on languages other than English hasn't been measured.

## Other limits

- Between daily signed checkpoints, someone with database-owner rights could rewrite recent audit entries unless a SIEM copy is configured.
- Rate limits are per process and per replica.
- The internal certificate authority lasts 10 years and has no rotation tool yet.
- Single logout and IdP-initiated sign-in aren't built. Linked installs have no shared sign-in, rule sync or combined audit yet.
