# Glossary

| Term | Meaning |
| --- | --- |
| **Access rule** (policy) | A published rule saying who may do what with which data, and what a reveal returns |
| **Approved network** | An IP range, such as your office or VPN, that rules can require |
| **Audit log** | The append-only, hash-chained record of every access and change |
| **Blind index** | A keyed hash that lets a value be found without decrypting it |
| **Break-glass** | Emergency access outside the normal rules, approved by another admin, for a limited time |
| **Check rule** (validator) | A test a pattern's match must pass, such as a check digit |
| **Client token** | A single-use token your server mints for a secure component |
| **Cloak setting** | What each kind of data becomes before a prompt leaves: placeholder, stand-in name, range |
| **Connection** | Something that sends data through Onshore: a log pipeline, AI route, proxy route, support tool |
| **Country pack** | A country's ID, account and phone formats, with check digits; built in or your own |
| **Data plane / control plane** | The services that touch values, and the ones that hold configuration |
| **Data type** (entity) | A kind of sensitive value Onshore finds, built in or your own |
| **Detection** | Finding sensitive values in free text and JSON |
| **Digital twin** | The sealed map from placeholders back to real values, kept for a set time |
| **Edition** | Free, Enterprise or Onshore Cloud |
| **Everywhere pack** | Names, emails, cards, amounts and phone numbers, on for every vault |
| **Field** | One kind of value in a vault, with its token and masking settings |
| **Flow** | Data moving from one of your systems to a destination, on the residency map |
| **Key holder** | A person holding one of the five shares that unseal the key service |
| **Linked install** | An install in another country reporting to your main console (Enterprise) |
| **Masked** | Part of a value shown, such as the last four digits |
| **Purpose** | The reason a person gives for a reveal, recorded in the audit log |
| **Residency map** | Every system and vendor holding your data, with each flow's status from evidence |
| **Resident check** | A yes-or-no question about a stored value, answered in the country |
| **Scope definition** | What your organisation counts as in-scope data, as counsel advised |
| **Sealed** | The key service's state after a restart, until key holders unseal it |
| **Service account** | An identity your systems use to call the API, with a key pair |
| **Subject** | A person whose values are in a vault, grouped by your customer reference |
| **Token** | What your systems keep in place of a value, such as `tok_uk_nino_7Hq2xP9LmA4c` |
| **Vault** | Where real values are kept, encrypted, in one country |
| **Watch only** | A connection or data type that counts what it would catch and changes nothing |
